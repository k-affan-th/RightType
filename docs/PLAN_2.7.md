# แผน RightType 2.7: ทัวร์แนะนำแอป

เป้าหมาย: ผู้ใช้เข้าใจว่าแอปทำอะไรได้บ้าง (โดยเฉพาะ Palette ที่ทรงพลัง และฟีเจอร์ที่เคอร์เซอร์) จากการเห็นและลองทำ ไม่ใช่จากการอ่านข้อความ
กติกาเดิมไม่เปลี่ยน: ไม่มีโค้ดเครือข่าย, ไม่เก็บสิ่งที่พิมพ์ลงดิสก์ (ธงเดียวที่เพิ่มคือ `tour_done` ใน config)

## ทำไมเป็น 2 แบบ

Palette รับแป้นผ่าน keyboard hook โดยอาศัยว่าหน้าต่างหน้าสุดต้องเป็น Palette เองหรือหน้าต่างที่เปิดมันขึ้นมา (`palette::is_open`) กล่องอธิบายที่เป็นหน้าต่างแยกทับ Palette จะรบกวนกลไกนี้ จึงแบ่งเป็น:

1. **ไฮไลต์** บนหน้าต่าง Settings: หรี่หน้าต่าง เจาะช่องรอบจุดที่อธิบาย กล่องอธิบาย (หน้าต่างปกติ ใช้ Tab/Enter/Esc ได้) มีก่อนหน้า/ถัดไป/ข้าม
2. **สนามฝึก**: หน้าต่างเดียวที่มีช่องพิมพ์และแผงโจทย์ในตัว ให้ลองทำจริง (เปิด Palette จากสนามฝึก ค้นหา พิมพ์ที่เคอร์เซอร์) แผงติ๊กถูกเมื่อผลในช่องตรงกับที่คาด

## บทและขั้น

ไฮไลต์ (Settings):
- **A. แก้คำผิดภาษา**: ปุ่มโหมด (Auto / Suggest / Manual) → สวิตช์ "RightType is on" → หน้า Hotkeys (ปุ่ม Change)
- **B. คำและแอปของคุณ**: Learned words → Snippets → Ignored apps (โหมดต่อแอป)
- **C. เครื่องมือแป้นพิมพ์**: ปุ่มทั้งสี่ใน Tools → Keyboard health
- **D. ความเป็นส่วนตัว**: การ์ดคำมั่นสัญญา → ปุ่มอัปเดต

สนามฝึก:
1. แก้คำผิดภาษา: พิมพ์ `l;ylfu` + เว้นวรรค (หรือ Shift+Backspace)
2. Palette: เปิดด้วย Ctrl+Alt+Space, ค้น "amount" แล้ว Enter
3. Palette กับข้อความที่เลือก: เลือกคำ แล้วเปิด Palette เห็น "Add “คำ”"
4. ที่เคอร์เซอร์: `x^2` แล้วกด Tab, แตะ Shift สองครั้งเพื่อค้นอักขระ

## วิธีทำ (ลำดับ)

- T1 ตัวไฮไลต์: หน้าต่างโปร่งใสคลิกทะลุ (layered, ช่องโหว่ด้วย GDI+) และกล่องอธิบาย
- T2 สคริปต์ขั้นของบท A–D (หาจุดที่ไฮไลต์จากข้อความของปุ่ม; เปลี่ยนหน้า Settings ด้วยการคลิกปุ่มเมนูจริง)
- T3 สนามฝึกและตัวตรวจว่าทำสำเร็จ (อ่านข้อความในช่อง ไม่ฉีดแป้นเอง)
- T4 จุดเรียก: ปุ่มใน Welcome/Help, แถวใน Palette, เมนูถาด; `tour_done`
- T5 ข้อความไทยและอังกฤษ (เขียนใหม่ ไม่ได้แปลตรงตัว), ภาพทุกขั้นทั้งมืด/สว่าง/ไทย, เทสต์ว่าทุกขั้นมีข้อความและจุดหมาย
- PR แยกจาก #20 (ฐานคือ branch ของ #20 จนกว่าจะ merge)

## ที่ตั้งใจไม่ทำ

- ไฮไลต์ในแอปอื่น (Word, เบราว์เซอร์): ทำไม่ได้โดยไม่ล้ำเส้นความเป็นส่วนตัว จึงใช้สนามฝึกแทน
- ทัวร์ที่บังคับดู: ข้ามได้ทุกขั้น เรียกซ้ำได้ทุกเมื่อ

## สถานะ

- ทำแล้ว: ไฮไลต์ 4 บท (11 ขั้น) ต่อกันอัตโนมัติ, เรียกจากเมนูถาด "ดูทัวร์แนะนำ…", ข้อความไทย/อังกฤษ, เทสต์ทุกขั้นมีข้อความและจุดหมาย
- เลื่อน: สนามฝึก เพราะ keyboard hook และ UI Automation ไม่ทำงานกับหน้าต่างของ RightType เอง (เพื่อกันแป้นหลุดตอน hook ช้า) การแก้คำและอ่านข้อความที่เลือกจึงลองจริงในหน้าต่างของตัวเองไม่ได้ ต้องออกแบบใหม่ก่อน
- เลื่อน: ธง `tour_done` และการเปิดทัวร์อัตโนมัติ (ตอนนี้เปิดเมื่อผู้ใช้สั่งเท่านั้น)
