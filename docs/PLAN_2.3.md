# แผน RightType 2.3: ผู้ช่วยคีย์บอร์ด (ร่าง)

สถานะ: ร่าง ยังไม่เริ่มทำ

เจ้าของสั่ง (2026-10-02):
- รวมทุกไอเดียในแผนนี้ ไม่ต้องคัดออก
- ถ้ายังไม่เสร็จครบ ให้ทำต่อจนเสร็จแล้วค่อยปล่อย 2.3.0
- ข้อที่เคยให้เลือก เจ้าของเลือกตามที่แนะนำแล้ว (ดูท้ายไฟล์)

## เป้าหมาย

RightType คือ **ผู้ช่วยทุกเรื่องของคีย์บอร์ดบน Windows สำหรับคนไทย**:

| หมวด | ทำอะไร |
|---|---|
| แก้ | พิมพ์ผิดแป้น ปุ่มลัดเพี้ยนตอนแป้นไทย ปุ่มค้าง ปุ่มเบิ้ล |
| บอก | ปุ่มลัดของแอปที่ใช้อยู่ ปุ่มที่เปิดค้างไว้โดยไม่รู้ตัว ความเสี่ยง |
| ดูแล | ล็อกแป้นตอนทำความสะอาด ทดสอบปุ่ม ตรวจสุขภาพแป้นและการตั้งค่า |
| ฝึก | ย้ายแป้นและฝึกพิมพ์ เป็นเครื่องมือหนึ่ง ไม่ใช่ตัวหลักของแอป |

คำสัญญาเดิมยังอยู่ครบ:
- ไม่มีโค้ดเครือข่าย (CI ตรวจ)
- ไม่เก็บสิ่งที่พิมพ์ลงดิสก์
- ข้อมูลใหม่ที่เก็บเป็น metadata ผู้ใช้ต้องเปิดเอง และบันทึกใน THREAT_MODEL

สิ่งที่ไม่ทำ:
- เชื่อมเครื่องอื่น
- ตารางคะแนนออนไลน์
- ประวัติคลิปบอร์ด
- ระบบ remap หรือ macro เต็มรูปแบบ (PowerToys มีแล้ว)

## หมวด P: เร็วและนิ่งขึ้น (ทำก่อน เพราะทุกฟีเจอร์ใหม่ใช้ตัวดักแป้นเดียวกัน)

**P1 แยกงานที่ต้องรอแอปออกจากตัวดักแป้น** — ✅ ทำแล้วในรูปแบบ "งบเวลาต่อปุ่ม" (ดูหมายเหตุ)
- หมายเหตุ (2026-10-02): ตัวเลขจาก P2 บน CI บอกว่าเวลาที่ช้าที่สุดมาจากการรอที่ตั้งใจไว้เอง (เว้น 40 ms ระหว่างลบกับพิมพ์, 150 ms ในแอปที่เคยเพี้ยน, รอคำตอบโฟกัส 60 ms, รอช่องข้อความ) แต่ละอย่างมีเพดาน แต่ผลรวมไม่มี
- จึงให้ทุกการรอในตัวดักแป้นใช้ "งบ" ร่วมกัน 200 ms ต่อปุ่ม ซึ่งรับประกันได้ว่าไม่เกินเวลาที่ Windows ยอมโดยไม่ต้องพักปุ่มไว้แล้วส่งใหม่ (ซึ่งเสี่ยงทำปุ่มหายหรือสลับลำดับ)
- CI e2e ล้มถ้าปุ่มไหนใช้เวลาเกิน 250 ms
- ด้านล่างคือแบบเดิมที่พิจารณาไว้ เก็บไว้เผื่อวันหนึ่งตัวเลขบอกว่าต้องใช้
- ปัญหา: ตัวดักแป้นตัดสินใจเร็ว (ช้าสุด 2.9 ms) แต่การแทนคำในช่องข้อความต้องรอแอปตอบ ถ้ารอนานเกินที่ Windows อนุญาต Windows จะปล่อยปุ่มผ่านไปเอง (บั๊ก `lสวัสดี`) และอาจถอดตัวดักทิ้ง
- ทางแก้: ตัวดักแป้นกลืนปุ่มที่จบคำไว้ แล้วส่งงาน "แทนคำ + ส่งปุ่มที่จบคำ" ไปให้เธรดทำงาน
  - ปุ่มที่กดตามมาระหว่างนั้นถูกพักไว้ในคิวที่จำกัดขนาด แล้วส่งตามลำดับเดิมเมื่องานเสร็จ
  - ถ้ารอเกิน 250 ms ให้ปล่อยทั้งคิวตามลำดับและเลิกแก้คำนั้น
- ทดสอบ: e2e หน้าต่างที่ตอบช้า (`hang` มีอยู่แล้ว) ต้องไม่มีตัวอักษรหลุดหรือสลับลำดับ

**P2 วัดเวลาต่อปุ่มบน Windows จริง**
- จับเวลาแต่ละครั้งที่ตัวดักแป้นทำงาน แล้วเก็บเฉพาะตัวเลข (มัธยฐาน, 99th, ช้าสุด) ลงรายงานปัญหา ไม่เก็บว่ากดปุ่มอะไร
- CI e2e ล้มถ้าช้าสุดเกิน 50 ms

**P3 เปิดเร็ว กินแรมน้อย**
- วัดเวลาเปิดโปรแกรมและหน่วยความจำก่อน แล้วลดจุดที่คุ้ม เช่น พจนานุกรมแบบบีบอัด หรือโหลดแป้นที่ไม่ได้ใช้เมื่อจำเป็น
- บันทึกตัวเลขก่อนและหลังใน `docs/TYPING_BENCHMARK.md`

**P4 หน้า "แอปไหนแก้ได้ดีแค่ไหน"**
- ใช้ผลตรวจหลังแก้ (verify) นับเป็นตัวเลขต่อแอป เช่น `notepad.exe: แก้ 120 ครั้ง ตรงทุกครั้ง`
- เก็บในหน่วยความจำ หรือลงดิสก์ถ้าเปิดสถิติข้ามรอบไว้แล้ว

## หมวด K: ปุ่มลัดและการสลับภาษา

**K1 ปุ่มลัดเพี้ยนตอนแป้นไทย**
- ปัญหา: บางเว็บแอปและบางโปรแกรมอ่านปุ่มลัดจากตัวอักษร ตอนแป้นไทย Ctrl+C จึงกลายเป็น Ctrl+แ
- ขั้นแรกพิสูจน์ก่อน: ทำหน้าทดสอบใน e2e ที่อ่าน `event.key` เทียบกับ `event.code` เพื่อยืนยันว่าเป็นจริงที่ไหนบ้าง
- ทางแก้: ในแอปที่อยู่ในรายการ (ผู้ใช้เพิ่มเองได้) เมื่อกด Ctrl/Alt + ปุ่มตัวอักษรตอนแป้นไทย ให้สลับเป็นอังกฤษชั่วคราว ส่งปุ่มลัด แล้วสลับกลับ

**K2 ดูปุ่มลัดของแอปที่ใช้อยู่**
- กด Ctrl ค้าง 1 วินาที (ตั้งค่าได้ / ปิดได้) จะขึ้นแผ่นรายการปุ่มลัด ค้นหาได้ด้วยชื่อไทยหรืออังกฤษ กดเลือกเพื่อสั่งงานได้เลย
- ที่มาของรายการ:
  - (ก) อ่านจากเมนูของแอปผ่าน UI Automation (`AcceleratorKey`) ใช้ได้กับ Notepad, Office, Explorer, Paint และแอป Win32 ทั่วไป
  - (ข) รายการที่ทำมาให้ในตัวสำหรับแอปที่ไม่มีเมนู ได้แก่ Chrome/Edge, VS Code, LINE, Discord, Excel (ปุ่มลัดที่ไม่มีในเมนู), Windows เอง (Win+…)
- อ่านแค่หน้าตาแอป ไม่อ่านข้อความ

**K4 เตือนเมื่อปุ่มลัดของ RightType ชนกับของแอปอื่น**: ตรวจตอนตั้งค่า โดยลองจองปุ่มลัดดู

**K5 ปุ่มสลับภาษาปุ่มเดียว**: เลือกได้ว่าจะใช้ Right Alt, Right Ctrl หรือ CapsLock (มีอยู่แล้ว)

**K6 กดปุ่มค้างเพื่อเลือกอักขระพิเศษ** (แบบ macOS)
- กด `.` ค้าง → … · •
- กด `-` ค้าง → – —
- กด `4` ค้าง → ฿ €
- ตอนแป้นไทย กด `ๆ` ค้าง → ฯ ฯลฯ
- ปิดได้ และไม่ทำงานในช่องรหัสผ่านกับแอปในรายการความปลอดภัย

## หมวด C: ดูแลคีย์บอร์ด (ใหม่)

**C1 โหมดทำความสะอาดคีย์บอร์ด** (ไอเดียของเจ้าของ)
- เปิดจาก tray, palette หรือปุ่มลัด แล้วนับถอยหลัง 3 วินาทีก่อนล็อก
- จอแสดง "กำลังทำความสะอาด" ตัวใหญ่ พร้อมเวลาที่เหลือ
- ระหว่างล็อก:
  - กลืนทุกปุ่ม รวมปุ่ม Windows, Alt+Tab, ปุ่มสื่อ (เสียง เล่น/หยุด) และปุ่มเรียกแอป (เครื่องคิดเลข เมล เบราว์เซอร์)
  - ไม่ส่งอะไรไปยังแอปเลย
  - ล็อกทัชแพดหรือเมาส์ด้วยได้ ถ้าเลือก
- ปลดล็อกด้วย:
  - คลิกปุ่ม "เสร็จแล้ว" ด้วยเมาส์ (ถ้าไม่ได้ล็อกเมาส์)
  - หรือปลดเองเมื่อครบเวลา (ค่าเริ่ม 60 วินาที สูงสุด 5 นาที)
  - Ctrl+Alt+Del ใช้ได้เสมอเป็นทางออกฉุกเฉิน
- **ข้อจำกัดที่ต้องบอกผู้ใช้ตรงๆ:**
  - ปุ่ม Fn, ปรับความสว่าง, เปิดปิด Wi-Fi และปุ่มเครื่องบินบนโน้ตบุ๊กหลายรุ่น ทำงานในเฟิร์มแวร์ของเครื่อง ซอฟต์แวร์ใดๆ บน Windows กันไม่ได้
  - ปุ่มเปิดเครื่อง กับ Ctrl+Alt+Del กันไม่ได้ (ตั้งใจให้เป็นแบบนั้น)
  - หน้าจอบอกว่าปุ่มไหนบ้างที่ยังกันไม่ได้
- ระหว่างล็อกแสดงปุ่มที่ถูกกดบนแป้นบนจอ เพื่อดูว่าเช็ดครบทุกปุ่มหรือยัง

**C2 ทดสอบคีย์บอร์ด**
- แป้นบนจอสว่างเมื่อกดแต่ละปุ่ม และจำว่าปุ่มไหนกดแล้ว
- หาปุ่มที่ไม่ตอบ และปุ่มที่ส่งค่าผิด
- ใช้คู่กับ C1 ได้ เช่น ทำความสะอาดเสร็จแล้วทดสอบต่อ

**C3 แก้ปุ่มเบิ้ล**
- ปัญหา: สวิตช์ที่สึกหรือมีฝุ่นทำให้กดครั้งเดียวได้สองตัว (`hhello`) โน้ตบุ๊กเก่าเป็นบ่อย
- ตรวจหา: ปุ่มเดียวกันลง–ขึ้น–ลงภายในไม่กี่สิบมิลลิวินาที ซึ่งนิ้วคนทำไม่ได้
- เมื่อเจอ RightType บอกว่าปุ่มไหน แล้วเสนอเปิดตัวกรองเฉพาะปุ่มนั้น
- เก็บแค่รหัสปุ่มกับเวลาห่าง ไม่เก็บข้อความ

**C4 ตรวจสุขภาพคีย์บอร์ด** (หน้าเดียว แต่ละข้อมีปุ่ม "แก้ให้")
- Shift, Ctrl หรือ Alt ค้าง (เจอบ่อยหลัง Remote Desktop): ปล่อยให้
- Sticky Keys หรือ Filter Keys เปิดอยู่ (มักเกิดจากกด Shift 5 ครั้ง หรือกด Shift ขวาค้าง): ปิดให้ หรือปิดทางลัดที่เปิดมันขึ้นมา
- ติดตั้งแป้นไทยซ้ำสองแบบ หรือมีแป้นที่ไม่ได้ใช้: เปิดหน้าตั้งค่าภาษาให้
- ปุ่มสลับภาษาของ Windows ชนกับปุ่มลัดอื่น เช่น Ctrl+Shift ใน VS Code
- ระบบแก้คำอัตโนมัติของ Windows เปิดอยู่ (มีใน About แล้ว จะย้ายมาที่นี่)
- NumLock, CapsLock หรือ Insert เปิดค้าง
- ปุ่มเบิ้ลที่ C3 เคยเจอ

**C5 เครื่องสแกนบาร์โค้ดตอนแป้นไทย**
- ปัญหา: เครื่องสแกนส่งปุ่มเหมือนคีย์บอร์ด US ถ้าแป้นไทยเปิดอยู่ บาร์โค้ด `8851234567890` จะออกมาเป็นอักษรไทย ร้านค้าในไทยเจอบ่อยมาก
- ตรวจหา:
  - อ่านว่าปุ่มมาจากอุปกรณ์ไหนผ่าน Raw Input
  - ความเร็วเกินมือคน (หลายตัวภายในไม่กี่ ms) ตามด้วย Enter
- แก้: แปลงชุดนั้นกลับเป็นตัวเลขหรือตัวอักษรอังกฤษ หรือจำอุปกรณ์นั้นไว้ให้พิมพ์อังกฤษเสมอ

**C6 กันคีย์บอร์ดปลอม** (เช่น USB ที่แอบพิมพ์คำสั่ง)
- เมื่อมีอุปกรณ์คีย์บอร์ดใหม่เสียบเข้ามา แล้วพิมพ์เร็วเกินมือคนทันที (โดยเฉพาะ Win+R ตามด้วยคำสั่ง) ให้หยุดรับปุ่มจากอุปกรณ์นั้นแล้วถามผู้ใช้
- อุปกรณ์ที่อนุญาตแล้ว เช่น เครื่องสแกนของ C5 จำไว้ด้วยรหัสอุปกรณ์ (metadata)
- ปิดได้

**C7 แป้นต่ออุปกรณ์**
- คีย์บอร์ดภายนอกเป็นอังกฤษ คีย์บอร์ดโน้ตบุ๊กเป็นไทย (ใช้ Raw Input ร่วมกับ C5/C6)
- ต้องพิสูจน์ก่อนว่าสลับแป้นทันโดยไม่มีตัวหลุด ถ้าทำไม่ได้จะรายงานพร้อมหลักฐาน ไม่ใช่ตัดทิ้งเงียบๆ

**C8 แสดงปุ่มที่กดบนจอ** (สำหรับสอน อัดคลิป หรือนำเสนอ)
- แสดงปุ่มลัดและปุ่มที่กดที่มุมจอ
- เปิดเองเท่านั้น และไม่แสดงอะไรเลยในช่องรหัสผ่านและแอปในรายการความปลอดภัย
- โหมดค่าเริ่มแสดงเฉพาะปุ่มลัด ไม่แสดงตัวอักษร

**C9 เตือนพักมือ**
- นับจำนวนปุ่มต่อชั่วโมง (ตัวเลขเท่านั้น) แล้วเตือนให้พักเมื่อพิมพ์ต่อเนื่องนาน
- เปิดเองเท่านั้น

## หมวด T: ย้ายแป้นและฝึกพิมพ์ (ทำให้เสร็จใน 2.3 ตามที่สั่ง)

| รหัส | ฟีเจอร์ |
|---|---|
| T1 | หน้าต่างฝึกพิมพ์ บทเรียนทีละแถวแป้น วัดความเร็วและความแม่นยำ ใช้ได้กับเกษมณี ปัตตะโชติ มนูญชัย และอังกฤษ |
| T2 | ข้อความฝึกสุ่มจากคำในพจนานุกรมในตัว ใช้เฉพาะปุ่มที่ปลดล็อกแล้ว |
| T3 | ฝึกปุ่มที่ผิดบ่อย นับจากการฝึกเท่านั้น |
| T4 | เกม: แข่งกับเวลา 60 วินาที และคำตก เล่นด้วยแป้นอย่างเดียว |
| T5 | โหมดย้ายแป้น: แป้นบนจอของแป้นใหม่ค้างไว้ระหว่างทำงานจริง ปุ่มที่คล่องแล้วค่อยๆ จางหายไป |
| T6 | แป้นบนจอแสดงสีตามอัตราผิดของแต่ละปุ่ม (จากการฝึก) |
| T7 | แบบฝึกเฉพาะภาษาไทย: ลำดับสระ–วรรณยุกต์ ตัวที่ต้องใช้ Shift เลขไทย ฯ ๆ |
| T8 | ความคืบหน้า: กราฟรายวัน เก็บเมื่อผู้ใช้เปิดเอง ไม่เกิน 365 แถว |

- เปิดเป็นหน้าต่างแยกด้วย Ctrl+Alt+T, จาก tray หรือ palette
- ระหว่างฝึก RightType ไม่แก้คำในหน้าต่างฝึก

## หมวด S: หน้าตั้งค่า

**S1 หน้าใหม่ "แป้นพิมพ์"**
- รวมสวิตช์ที่ตอนนี้อยู่แค่ใน palette: ที่อยู่เว็บ/ตัวเลข, ตัวหนอน, NumLock, Insert, แท็กรหัสผ่าน, เปลี่ยนภาษากลับเมื่อกดพร้อมปุ่มลัด, เติมคำไทย
- เพิ่มสวิตช์ใหม่: K1 K2 K5 K6 C3 C5 C6 C8 C9
- ย้ายตัวเลือกแป้นไทยมาจากหน้าปุ่มลัด
- หน้านี้เลื่อนได้ แก้ปัญหาหน้า General ที่เต็ม

**S2** ทุกสวิตช์มีเคส e2e ทั้งตอนเปิดและตอนปิด

**S3 หน้า "เครื่องมือ"**: ทางเข้าของ C1 C2 C4 และ T1 พร้อมคำอธิบายสั้นๆ

## ข้อมูลที่เก็บ (เพิ่มใน THREAT_MODEL)

| ข้อมูล | เก็บ | หมายเหตุ |
|---|---|---|
| เวลาต่อปุ่มของตัวดักแป้น (P2) | ตัวเลขสรุปในรายงานปัญหา | ไม่มีรหัสปุ่ม |
| ผลแก้ต่อแอป (P4) | ชื่อ exe + จำนวน | ไม่มีคำ |
| ปุ่มเบิ้ล (C3) | รหัสปุ่ม + เวลาห่าง | ไม่มีลำดับปุ่ม |
| อุปกรณ์ที่อนุญาต (C5–C7) | รหัสอุปกรณ์ + ชื่อที่ผู้ใช้ตั้ง | |
| ปุ่มที่กดระหว่างฝึก (T) | ไม่เก็บ | zeroize เมื่อจบบท |
| ผิดต่อปุ่มจากการฝึก (T3 T6) | ตำแหน่งปุ่ม + จำนวน | |
| คะแนนรายวัน (T8) | เปิดเอง, ไม่เกิน 365 แถว | |
| จำนวนปุ่มต่อชั่วโมง (C9) | หน่วยความจำเท่านั้น | |

## ลำดับงาน

1. **P1 + P2:** ฐานที่ทุกอย่างต้องใช้
2. **S1 + S2 + K5:** หน้าตั้งค่าใหม่ ที่ใส่สวิตช์ของทุกข้อที่ตามมา
3. **C1 + C2 + C4:** ทำความสะอาด ทดสอบปุ่ม ตรวจสุขภาพ (ใช้แป้นบนจอที่มีแล้ว)
4. **C3 + C5 + C6 + C7:** Raw Input และอุปกรณ์
5. **K1 + K2 + K4 + K6:** ปุ่มลัด
6. **T1–T8:** ฝึกพิมพ์
7. **P3 + P4 + C8 + C9 + S3**
8. **ปล่อย 2.3.0:**
   - CHANGELOG, THREAT_MODEL, README, ภาพหน้าจอ
   - e2e ครบทุกข้อ
   - ปล่อยเมื่อเจ้าของสั่งเท่านั้น

แต่ละขั้นเป็น commit แยก และ CI ต้องเขียวก่อนเริ่มขั้นถัดไป

## การตรวจ (ทุกขั้น)

- fmt, clippy `-D warnings` บน Linux และ Windows, `cargo test`
- `false_positive_audit --check` และ `typing_benchmark --check`
- ภาพ Wine ของ UI ใหม่ทุกหน้า: TH/EN, สว่าง/มืด, 96/144 DPI
- เคส e2e ของทุกฟีเจอร์ที่ทดสอบบน CI ได้

C1 ล็อกปุ่มทดสอบบน CI ได้ แต่ข้อเหล่านี้ทดสอบบน CI ไม่ได้ จะใส่ใน `e2e/release_gaps.py` ให้ลองบนเครื่องจริง:
- ปุ่ม Fn และปุ่มพิเศษของโน้ตบุ๊ก (C1)
- การเสียบอุปกรณ์จริง (C5 C6 C7)

## ข้อที่ตัดสินแล้ว

- สถิติปุ่มสำหรับการฝึก (T3 T6) นับจากการฝึกเท่านั้น
- ความคืบหน้า (T8) เก็บคะแนนรายวันเมื่อผู้ใช้เปิดเอง
- เกม (T4) เริ่มที่แข่งกับเวลาและคำตก
- หน้าฝึกเป็นหน้าต่างแยก
- รวมทุกไอเดียใน 2.3 ไม่คัดออก ทำจนเสร็จแล้วค่อยปล่อย
