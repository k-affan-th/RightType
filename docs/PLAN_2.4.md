# แผน RightType 2.4: ค้นและสั่งได้ทุกอย่างที่เคอร์เซอร์

สถานะ: ร่าง (2026-10-03) เจ้าของเห็นด้วยกับทิศทางแล้ว ยังไม่เริ่มทำ

## เป้าหมาย

เจ้าของต้องการ (2026-10-03):
- ปุ่มลัดของแอปต่างๆ ใช้เป็น "คำสั่ง" ที่ค้นด้วยชื่อได้
- ทำงานกับ LaTeX และสมการได้
- อักขระพิเศษทุกตัวที่เป็นไปได้ ค้นได้ทั้งจากคำอธิบายและจากรูปที่คล้าย
- ช่องค้นหาทุกที่รองรับการพิมพ์ด้วยแป้นภาษาไหนก็ได้
- ไม่เพิ่ม pane ใหม่ ให้ขึ้นเป็นรายการเดาคำตรงที่พิมพ์ แบบที่ VS Code มี

แนวทางที่เลือก (แทนแบบ "ตัวนำ" เช่น `\` `::` `>>` ที่ต้องจำ ชนกับโค้ดและแชต และต้องลบทิ้งทีหลัง):
- **เรียกที่เคอร์เซอร์ด้วยปุ่มเดียว** คำค้นไม่ลงไปในเอกสาร
- **แนะนำแบบเงา** สำหรับรูปแบบที่ชัดเจน โดยไม่ต้องเรียก
- **ใช้ข้อมูลมาตรฐานของ Unicode** แทนการทำรายการเองทั้งหมด
- **อ่านคำสั่งจริงของแอป** ผ่าน UI Automation

คำสัญญาเดิมยังอยู่ครบ:
- ไม่มีโค้ดเครือข่าย (CI ตรวจ)
- ไม่เก็บสิ่งที่พิมพ์ลงดิสก์
- ข้อมูลใหม่ที่เก็บเป็น metadata ผู้ใช้ต้องเปิดเอง และบันทึกใน THREAT_MODEL

## หลักหน้าตาและการใช้งาน (เจ้าของสั่ง 2026-10-03)

> "อยากให้แอปมีแอนิเมชั่นที่ลื่นไหล แล้วก็ยูไอที่น่าใช้งาน มีไอคอน ช่วยในบางพื้นที่ในการสื่อสาร และทำให้การใช้งานนั้นลื่นไหล"

ทุกหน้าต่างและทุกอย่างใหม่ใน 2.4 ต้องเป็นตามนี้:

- **แอนิเมชันลื่น ไม่ขวางการทำงาน**
  - เข้า: จางเข้า + ขยับขึ้นเข้าที่ (`motion::frame`, 140 ms)
  - ออก: จางออก (220 ms)
  - การเลือก: แถบเลื่อนไปแถวใหม่ (`motion::slide`, 110 ms)
  - ทุกเฟรมคำนวณจากเวลาที่ผ่านไป timer มาช้าก็แค่ข้ามเฟรม ไม่ทำให้ช้าลง
  - แอนิเมชันไม่ทำให้การพิมพ์รอ ตัวอักษรลงแอปทันที แอนิเมชันแค่ตามมา
  - วาดครั้งเดียวต่อเฟรม ไม่มีตัวควบคุมย่อยหลายสิบตัว (บทเรียนจาก 2.3 ที่ทำให้ปุ่มหาย)
- **ไอคอนช่วยสื่อสาร**
  - ใช้ฟอนต์ไอคอนของ Windows (Segoe Fluent Icons / MDL2 Assets) แบบเดียวกับ palette
  - ใช้บอกชนิดของสิ่งที่เห็น เช่น แว่นขยายที่ช่องค้น และโน้ตที่คำย่อ
  - ไม่ใช้ไอคอนประดับเฉยๆ
  - เครื่องไหนไม่มีฟอนต์ไอคอน ต้องยังอ่านรู้เรื่องด้วยข้อความ
- **ใช้ลื่น**
  - เปิดด้วยปุ่มเดียว ใช้ด้วยคีย์บอร์ดล้วน
  - บอกปุ่มที่ใช้ได้ที่ท้ายรายการ
  - ไม่แย่งโฟกัสจากแอป
- **ตรวจทุกครั้ง:** ภาพ Wine TH/EN สว่าง/มืด 96/144 DPI
  - ใน Wine ไม่มีฟอนต์ไอคอนของ Windows จึงเห็นแบบไม่มีไอคอน
  - ไอคอนจริงต้องดูบนเครื่อง Windows

## หมวด F: ค้นหาแบบเดียวกันทุกที่ (ทำก่อน เพราะทุกหมวดใช้)

**F1 ตัวค้นกลาง `righttype::find`** (ไม่เรียก OS ทดสอบได้บน Linux)
- palette, รายการปุ่มลัดของแอป และรายการที่เคอร์เซอร์ ใช้ตัวเดียวกัน
- เรียงตาม: ตรงทั้งคำ > ขึ้นต้นด้วย > อยู่กลางคำ > พิมพ์ผิดหนึ่งตัว

**F2 ไม่ขึ้นกับแป้น** แต่ละคำค้นลองหลายแบบ:
- ตามที่พิมพ์
- แปลงแป้นอังกฤษ↔ไทย (มีใน palette แล้ว ย้ายมาไว้ที่นี่): `ฟพนั` = `alpha`, `lux` = `ลูก`
- เทียบกับแป้นทุกแบบที่รองรับ ทั้งเกษมณี ปัตตะโชติ และมนูญชัย

**F3 คาราโอเกะ** (ถอดเสียงตามหลักราชบัณฑิตฯ แบบย่อ)
- `luksorn` → ลูกศร, `huachai` → หัวใจ
- เป็นตารางเสียงในตัว ไม่ใช่พจนานุกรมใหม่

**F4 ความเร็ว**
- ค้นในรายการ 150,000 ตัวต้องเสร็จภายใน 5 ms
- ทำบนเธรด UI หลังตัวดักแป้นคืนค่าแล้ว ไม่ทำในตัวดักแป้น (บทเรียนจาก 2.3: ปุ่มหายเมื่อเธรด UI ช้า)
- มี benchmark ใน `examples/` และเป็นด่านใน CI

## หมวด B: อักขระพิเศษทุกตัว

**B1 ชื่อ Unicode ทุกตัว** (ภาษาอังกฤษ)
- จาก `UnicodeData.txt` ราว 150,000 ตัว
- ข้ามตัวที่พิมพ์แล้วไม่เห็น เช่น control และ private use
- บีบอัดตอน build โหลดเมื่อใช้ครั้งแรก ขนาดโปรแกรมเพิ่มไม่เกิน 2 MB (วัดจริงก่อนตัดสินใจ)

**B2 คำค้นภาษาไทยจาก CLDR**
- `annotations/th.xml` และ `en.xml` มีคำค้นทางการของสัญลักษณ์และ emoji หลายพันตัว
- เช่น ลูกศร หัวใจ เครื่องหมายถูก

**B3 ค้นจากรูปคล้าย**
- ใช้ `confusables.txt` ของ Unicode (ราว 6,000 คู่ ตัวไหนหน้าตาคล้ายตัวไหน)
- เสริมด้วยตารางเขียนแทนที่คัดเอง: `o/`→ø ∅, `~=`→≈ ≅, `<=`→≤, `->`→→, `e^`→ê, `c,`→ç
- พิมพ์ตัวที่หน้าตาใกล้เคียงแล้วได้ตัวจริง

**B4 คำอธิบายไทยที่คัดเอง** ราว 1,500 ตัวที่ใช้จริง:
- คณิตศาสตร์
- สกุลเงิน
- เครื่องหมายวรรคตอน
- ตัวอักษรมีเครื่องหมาย
- สัญลักษณ์ไทย (ต่อจาก `thai_text::SYMBOLS` ที่มี 35 ตัว)

**B5 ใบอนุญาต: ตรวจแล้ว ผ่าน (2026-10-03)**
- Unicode Data, confusables และ CLDR ใช้ Unicode License V3 (ไฟล์ `LICENSE` ใน unicode-org/cldr และ unicode-org/unicodetools)
- ใช้ คัดลอก แก้ไข และแจกจ่ายได้ฟรี ทั้งในซอฟต์แวร์เชิงพาณิชย์ ขอแค่แนบประกาศลิขสิทธิ์ไปด้วย จึงใช้ร่วมกับ MIT ได้
- CLDR: ประกาศของ repo จำกัดการใช้เฉพาะเอกสารสเปก (UTS #35, LDML) ส่วน "เนื้อหาอื่นทั้งหมด" รวมถึงข้อมูล annotations ที่เราใช้ เป็น Unicode License V3
- ใส่ประกาศแบบคำต่อคำแล้วใน `THIRD_PARTY.md` (ทั้งของ unicodetools และ CLDR) และจะเพิ่มในหน้า About

**ผลสำรวจข้อมูลจริง (2026-10-03)**
- unicode.org ถูกบล็อกจากเครื่อง build นี้ จึงใช้ไฟล์เดียวกันจาก GitHub ของ unicode-org
  - `unicodetools/data/ucd/16.0.0/UnicodeData.txt`
  - `unicodetools/data/security/16.0.0/confusables.txt`
  - `cldr/common/annotations/{th,en}.xml`
- ตัวที่มีชื่อจริง (ไม่นับชื่ออัตโนมัติของ CJK/Hangul ที่ค้นไม่ได้ประโยชน์ และ control): 39,843 ตัว
  - ชื่อรวม 1.2 MB, ถ้าบีบอัด 237 KB
- โปรเจกต์ไม่มี crate บีบอัด จึงไม่เพิ่ม dependency ใหม่
  - เก็บชื่อเป็นดัชนีของตารางคำ (แบบที่ Unicode เองใช้บีบชื่อ) คาดว่าราว 0.5 MB
  - ถอดเมื่อใช้ครั้งแรก
- CLDR ภาษาไทยมีคำค้น 1,975 ชุด (สัญลักษณ์ 551 ชุด ที่เหลือเป็น emoji)
  - ตัวอย่าง: → "ลูกศร", € "ยูโร", ≈ "ประมาณ"
  - บางตัวไม่มี เช่น ✓ ต้องเติมใน B4
  - CLDR มีคำพิมพ์ผิดบ้าง เช่น "ผมรวม" ของ ∑ จะแก้ในตารางของเราเอง
- confusables มี 6,724 แถว

**B6 ผลลัพธ์**
- แสดงตัวอักขระขนาดใหญ่ ชื่อ และรหัส U+XXXX
- กดแล้วพิมพ์ลงที่เคอร์เซอร์: Unicode ผ่าน VK_PACKET แบบที่ใช้อยู่แล้ว

**ผลขั้นที่ 1 (2026-10-03)**
- **ข้อมูล:**
  - `tools/gen_chars.py` สร้างไฟล์จาก Unicode 16.0 และ CLDR
  - ชื่อ 28,490 ตัว: ตัดอักษรโบราณที่ไม่มีใครค้นออกเพิ่ม (cuneiform, hieroglyph ฯลฯ) อยู่ใน `names.bin` ขนาด 402 KB
  - คำค้น CLDR 1,975 ชุด และรูปคล้าย 208 แบบ
- **`righttype::chars`:**
  - สร้างตารางครั้งแรกที่ใช้ ใช้เวลา 9 ms และหน่วยความจำ 4.3 MB ตอนเปิดโปรแกรมไม่เสียอะไร
  - ค้น 1 ครั้งใช้ 4–7 ms (release, เครื่อง build)
  - คำค้นตัวเดียว เช่น `x` ช้าสุด เพราะเจอในชื่อหลายพันตัว เกินเป้า 5 ms เล็กน้อย
  - รายการจะกรองหลังหยุดพิมพ์ชั่วครู่ (แบบรายการปุ่มลัดของ 2.3) จึงไม่ค้นทุกปุ่ม
  - เดิมใช้ 250 ms ลดลงด้วยสามวิธี:
    - ตัดการอ่านแบบไทยออกเมื่อข้อความเป็นอังกฤษล้วน
    - เช็ค "มีคำค้นอยู่ในข้อความไหม" ก่อนจัดอันดับ
    - ลองคำพิมพ์ผิดเฉพาะเมื่อผลน้อยเกินไป

## หมวด A: รายการที่เคอร์เซอร์ (ไม่มี pane)

**A1 เรียกด้วยปุ่มเดียว**
- ค่าเริ่ม: Shift สองครั้ง (ภายใน 300 ms และไม่มีปุ่มอื่นคั่น) ตั้งเป็นปุ่มอื่นได้ หรือปิดได้
- ต้องพิสูจน์ใน e2e ว่าการพิมพ์ตัวใหญ่ปกติ (Shift+ตัวอักษร) ไม่เรียกโดยไม่ตั้งใจ

**A2 พิมพ์คำค้นแล้วไม่ลงเอกสาร**
- ตัวดักแป้นส่งปุ่มเข้ารายการโดยตรง แบบเดียวกับ palette และรายการปุ่มลัดใน 2.3
- ใช้ได้แม้ Windows ไม่ยกรายการขึ้นหน้าสุด (บทเรียนจาก 2.3)

**A3 หน้าตา**
- กล่องเล็กใต้เคอร์เซอร์ (ใช้ `caret.rs` ที่มีอยู่) หาเคอร์เซอร์ไม่ได้จะขึ้นกลางหน้าต่าง
- แสดงสูงสุด 8 แถว แต่ละแถวมีไอคอนชนิด ชื่อ และปุ่มลัดหรือตัวอักขระด้านขวา
- ใช้ลูกศร Enter Tab Esc และตัวเลข 1–8

**A4 รายการเดียวค้นได้ทุกอย่าง**
- คำสั่งของแอป (หมวด E)
- อักขระ (หมวด B)
- สมการ (หมวด D)
- emoji
- คำย่อ (snippets)
- เครื่องมือข้อความของ palette เดิม

**A5 เรียงตามบริบท**
- ในแอปที่มีคำสั่ง คำสั่งของแอปขึ้นก่อน
- คำค้นที่หน้าตาเป็นสมการ (`\`, `^`, `_`) ให้สมการขึ้นก่อน
- ใช้บ่อยขึ้นก่อน: นับเฉพาะเมื่อผู้ใช้เปิดเอง (A6)

**A6 จำคำสั่งที่ใช้บ่อยต่อแอป** (เปิดเอง)
- เก็บชื่อ exe, รหัสคำสั่ง และจำนวนครั้ง ไม่เก็บคำค้น
- ปิดแล้วลบไฟล์

**A7** ไม่ทำงานในช่องรหัสผ่านและแอปในรายการความปลอดภัย

## หมวด C: แนะนำแบบเงา (ไม่ต้องเรียก)

**C1 รูปแบบที่ชัด**
- พิมพ์เสร็จแล้ว แสดงตัวที่จะได้จางๆ ข้างเคอร์เซอร์ กด Tab ถึงจะเปลี่ยน
- ใช้ระบบเดียวกับโหมด Suggest
- ตัวอย่าง: `->` → →, `<=` → ≤, `!=` → ≠, `+-` → ±, `1/2` → ½, `(c)` → ©, `x^2` → x², `\alpha` → α

**C2 ไม่เปลี่ยนเองเด็ดขาด** ถ้าไม่กด Tab เงาจะหายเมื่อพิมพ์ต่อ

**C3 ปิดเป็นค่าเริ่มในโปรแกรมเขียนโค้ดและ terminal**
- ใช้รายการ code mode ที่มีอยู่ เพราะที่นั่น `->` และ `!=` มีความหมาย
- ปิดหรือเปิดต่อแอปได้

**C4 ด่านตรวจ**
- ขยาย `false_positive_audit` ให้รันกฎเงากับข้อความจริงทั้งชุด
- เงาต้องไม่ขึ้นในข้อความไทย/อังกฤษปกติเกินเกณฑ์ที่ตั้ง

**ผลขั้น C (2026-10-03)**
- `righttype::ghost` (ไม่แตะ OS) มีกฎ: ลูกศร ≤ ≥ ≠ ± ≈ เศษส่วน … – — และตัวยก `x^2`
  - ไม่เสนอเมื่อเป็นส่วนของสัญลักษณ์ที่ยาวกว่า (`<--`, `!==`, `....`) หรือเศษส่วนอยู่ในตัวเลขหรือวันที่ (`11/2`, `1/1/2`)
- ตัด `(c)` `(r)` `(tm)` ออก: ด่าน C4 พบว่า `(a) (b) (c)` เป็นรายการบ่อยกว่า © และรายการที่เคอร์เซอร์ค้น © ® ™ ได้ด้วยชื่อ
- คำสั่ง LaTeX ของสัญลักษณ์ตัวเดียว (`\\alpha` → α, `\\leq` → ≤) ก็เสนอด้วย ชื่อฟังก์ชันอย่าง `\\sin` ไม่เสนอ
- hook จำแค่ 16 ตัวอักษรล่าสุดในหน่วยความจำ ล้างเมื่อ Enter, Tab, ลูกศร, คลิก, คีย์ลัด หรือเปลี่ยนช่อง
- คำเสนอขึ้นเป็นป้ายใต้เคอร์เซอร์ `!=  →  ≠   ·   Tab` อยู่ 2 วินาทีเท่ากับเวลาที่ Tab ใช้ได้พอดี ไม่มีการเปลี่ยนที่มองไม่เห็น
- ปิดในโปรแกรมเขียนโค้ด ช่องรหัสผ่าน แอปบนรายการความปลอดภัย และแอปที่ปิดไว้
- สวิตช์อยู่ที่ Settings → แป้นพิมพ์ → ที่เคอร์เซอร์
- C4: `false_positive_audit --check` พิมพ์คำในพจนานุกรมทุกคำ (มีวงเล็บและเครื่องหมายวรรคตอน) และบทความตัวอย่างทีละตัว ผลคือขึ้นคำเสนอ 0 ครั้ง
- e2e: `ghosts` ใน Notepad: `a ->` แล้วกด Tab ได้ `a → b` และ `x != y` ที่ไม่กด Tab อยู่เหมือนเดิม

## หมวด D: สมการ

**D1 LaTeX → Unicode** (ไม่ใช้ OS ทดสอบได้)
- ตัวกรีก เครื่องหมายคำนวณ และลูกศร
- ตัวยก/ตัวห้อยที่ Unicode มี: `x^2` → x², `a_n` → aₙ
- ตัวพิเศษ: `\sqrt{x}` → √x, `\sum_{i=1}^{n}` → ∑ᵢ₌₁ⁿ, `\frac{1}{2}` → ½, `\frac{a}{b}` → a⁄b
- โครงสร้างที่ทำเป็นข้อความบรรทัดเดียวไม่ได้ (เศษส่วนซ้อน, matrix) จะบอกตรงๆ ว่าแปลงไม่ได้ ไม่เดา

**D2 แอปที่มีตัวเขียนสมการ** (Word, OneNote, PowerPoint)
- ส่ง LaTeX ให้ตัวเขียนสมการของแอปเอง: Alt+= แล้วใส่ข้อความในโหมด LaTeX
- ต้องพิสูจน์ก่อนว่าทำได้จากภายนอกและได้ผลเหมือนพิมพ์เอง
- ถ้าไม่ได้ ใช้ D1 แทน และบันทึกผลในแผน

**D3 แสดงผลก่อนเลือก** ในรายการที่เคอร์เซอร์ แสดงผลลัพธ์จริงของ LaTeX ที่พิมพ์

**ผลขั้น D1 + D3 (2026-10-03)**
- `righttype::latex::to_unicode`: กรีก เครื่องหมาย ลูกศร เซต ฟังก์ชัน ตัวยก/ตัวห้อยที่ Unicode มี `\sqrt` `\sqrt[3]` `\frac` (½, ¹²⁄₃₅, a/b, (x+1)/2) `\mathbb` และเครื่องหมายเน้น (`\hat` `\vec` `\bar`)
- ที่เขียนเป็นบรรทัดเดียวไม่ได้ จะบอกเหตุผลเป็นภาษาของหน้าจอ ไม่เดา:
  - เศษส่วนซ้อน
  - `\begin`
  - ตัวยกที่ Unicode ไม่มี เช่น `x^q` และ `\int_0^\infty` (ไม่มีตัวยก ∞)
  - คำสั่งที่ไม่รู้จัก
- รายการที่เคอร์เซอร์:
  - พิมพ์ LaTeX แล้ว แถวบนสุดคือผลลัพธ์จริง ตัวใหญ่ มีไอคอนสมการ
  - ถ้าแปลงไม่ได้ จะขึ้นแถวสีจางพร้อมไอคอนเตือนบอกเหตุผล เลือกไม่ได้ และ Enter ไม่ปิดรายการ ให้แก้คำค้นต่อได้
  - พิมพ์ `\al` จะได้รายการคำสั่งที่ขึ้นต้นแบบนั้น (α \alpha, ℵ \aleph)
- ภาพ Wine: วางตำแหน่งถูกต้อง แต่ GDI ของ Wine ไม่มี font fallback ตัวกรีกและตัวห้อยจึงเป็นกล่อง ต้องตรวจบน Windows จริง (Segoe UI + font linking)
- D2 (ตัวเขียนสมการของ Word/OneNote) ยังไม่เริ่ม ต้องพิสูจน์บน Windows จริงก่อน

## หมวด E: คำสั่งจริงของแอป

**E1 อ่านคำสั่งผ่าน UI Automation**
- อ่านปุ่ม เมนู และ ribbon ของหน้าต่างที่ใช้อยู่: ชื่อ, ปุ่มลัด (AcceleratorKey) และว่าสั่งได้ไหม (Invoke pattern)
- อ่านเฉพาะชื่อของตัวควบคุม ไม่อ่านเนื้อหาเอกสาร
- เก็บในหน่วยความจำ ล้างเมื่อเปลี่ยนหน้าต่าง

**E2 สั่งงาน**
- กดผ่าน Invoke pattern โดยตรง จึงใช้ได้แม้คำสั่งนั้นไม่มีปุ่มลัด
- ถ้า Invoke ไม่ได้ ใช้ปุ่มลัดจากตาราง 2.3

**E3 ช่วยให้จำปุ่มลัดได้**
- หลังสั่งผ่านรายการ บอกปุ่มลัดจริง เช่น "ครั้งหน้า: Ctrl+H"
- ปิดได้ ใช้ overlay เดิม

**E4 ขอบเขตที่ต้องพิสูจน์ก่อน** (บันทึกผลจริงทุกแอป)
- Office ribbon, Explorer, Notepad และแอป Win32 ทั่วไป: น่าจะได้
- Electron (VS Code, Discord) และเว็บ: ได้บางส่วน
- แอปที่ไม่เปิด UI Automation ใช้ตาราง 2.3 ต่อ

**E5 ความปลอดภัย**
- ไม่สั่งงานในแอปที่อยู่ในรายการความปลอดภัย
- คำสั่งที่ทำลายข้อมูล (Delete, ปิดโดยไม่บันทึก) ขอยืนยันก่อน

**ผลขั้น E ส่วนแรก (2026-10-03): คำสั่งจากเมนูและตาราง 2.3**
- รายการที่เคอร์เซอร์ค้นคำสั่งของแอปที่ใช้อยู่ได้:
  - ใช้เมนูของแอป (ชื่อและปุ่มลัด) ตาราง `shortcuts.txt` และคำสั่งของ Windows
  - ค้นได้ทั้งชื่อไทยและอังกฤษ เช่น พิมพ์ `close` ในหน้าจอภาษาไทยก็เจอ "ปิดหน้าต่าง"
- คำสั่งของแอปอยู่ก่อนอักขระที่ตรงพอกัน (+200): `close` ได้ "ปิดหน้าต่าง" ก่อน `)`
- กด Enter แล้วโปรแกรมจะกดปุ่มลัดนั้นให้ในแอป และขึ้น "ครั้งหน้ากด Ctrl+H ได้เลย" (E3)
- คำสั่งที่อาจทำให้งานหาย (ปิดหน้าต่าง/แท็บ, ลบ, ออก) ต้องกด Enter สองครั้ง ครั้งแรกจะขึ้น "กด Enter อีกครั้ง: …" พร้อมไอคอนเตือน (E5)
- E1/E2 (อ่านและสั่งผ่าน UI Automation Invoke สำหรับคำสั่งที่ไม่มีปุ่มลัด เช่น ribbon) ยังรอพิสูจน์บน Windows จริง
- e2e `caret_commands`: Shift สองครั้ง → `replace` → Enter แล้วต้องเปิดหน้าต่าง Replace ของ Notepad และไม่มีอะไรถูกพิมพ์ลงไป
